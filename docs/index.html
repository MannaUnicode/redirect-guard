Migrations lose traffic in quiet ways

After a rebuild, a re-platform or a domain move, old URLs keep their rankings only if every one of them lands, permanently and directly, on a page that can be indexed. These are the mistakes that slip through.

Missing redirects

An old URL answers 404, or still serves the old page when it should redirect.

/chi-siamo → 404

Temporary instead of permanent

A 302 or 307 where a 301 or 308 belongs, on the first hop or hidden later in the chain.

/prodotti → 302 → /shop

Chains and loops

Each extra hop slows crawling and users. Loops never resolve at all.

/a → /a/ → /b → /b/

Targets that can't be indexed

The redirect works, but the destination is noindex, canonicalised elsewhere, blocked by robots.txt or not 200.

→ 200 · noindex

Everything to the homepage

Dozens of old pages sent to /. Google may treat them as soft 404s and drop them.

12 URLs → /

Small inconsistencies

Lost query strings, http targets on an https site, www and non-www mixed together.

/p?id=3 → /product

How it works

One command, run before launch against staging and again after DNS cutover.

  1. Give it the old URLs

    A CSV, TSV or JSON redirect map, a plain list, or simply the sitemap you saved from the old site.

  2. It follows every hop

    Each redirect is requested by hand, so the full chain is recorded: status, Location and timing. Then it checks the final page's headers, meta robots, canonical and robots.txt.

  3. You get a verdict

    A readable report, plus JSON, Markdown, JUnit or GitHub annotations for CI. Exit code 1 on failures, so it can block a deploy.

Quickstart

No install needed. Write a two-column CSV, or point it at an old sitemap.

An empty to with status 410 or 404 means "removed on purpose": the check passes only if the page is really gone.

Staging first, then CI

Test your production redirect map against a staging host before DNS changes, then keep it as a regression test on every deploy.

Credentials and custom headers are sent only to the origins you are testing. If a redirect points to a CDN or a third-party domain, that request goes out without them, and header values never appear in reports.

Principles

  • Zero runtime dependencies. Node built-ins only, enforced by a test.
  • No telemetry, ever. It talks only to the URLs you give it, their redirects and the destination's robots.txt.
  • Polite by default. 4 parallel requests, optional per-host delay, retries that respect Retry-After.
  • Stable contract. Rule ids, exit codes and the JSON schema follow semantic versioning.
  • MIT licensed. Use it in client work, fork it, ship it.

Honest limits

  • It reads raw HTML. Meta tags injected by JavaScript are not seen.
  • Bot protection may answer 403 to non-browser clients. Allowlist your runner or test staging. It never tries to bypass challenges.
  • It checks the URLs you supply. It does not crawl to discover new ones.
